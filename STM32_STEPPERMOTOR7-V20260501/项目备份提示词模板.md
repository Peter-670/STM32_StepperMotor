## 指令

请按以下步骤为我处理这个项目：

### 第一步：通读项目

先全面阅读项目代码和配置文件，理解项目：
- 这是什么项目（功能、用途、技术栈）
- 硬件/软件架构是怎样的
- 关键的设计决策和特殊处理是什么
- 有哪些外部依赖

读完给我一个简短概述，确认理解正确后等我指示再继续。

### 第二步：编写详细说明文档

基于项目实际情况，写一份完整的 `README.md`，要求：

**内容要求：**
- 项目概述（一句话说清 + 核心功能列表）
- 系统架构设计（图文说明整体结构、关键设计思路和为什么这样设计）
- 硬件/软件配置详解（引脚、通道、时钟、参数等完整列出）
- 核心算法/逻辑的原理说明
- 通信协议或接口说明（如有）
- 编译/构建/部署步骤（前置条件、具体步骤、注意事项）
- 使用说明（典型操作流程、常见问题排查）
- 自定义修改指南（告诉使用者怎么改参数、怎么扩展）
- 文件结构说明
- 实用附录（速查表、换算公式等）

**格式要求：**
- 表格优于纯文字列表
- 可以适当增加一点表情包让说明文档更加生动形象，不要太多
- 代码块标明语言
- 章节锚点链接
- 中文书写，专业术语保留英文

### 第三步：创建 GitHub 备份文件夹

在项目根目录下新建文件夹，命名规则：`{项目名}-{版本号}`（大写，如 `STM32_StepperMotor7`）。

**备份原则：**
- 所有手写的源代码（`.c` `.h` `.s` 等）
- 项目配置文件（`.ioc` `.mxproject` 等，CubeMX/Keil/PlatformIO 等 IDE 的项目文件）
- 第三方驱动文件（项目中引用的独立驱动）
- 启动文件和链接脚本
- 第二步写的 `README.md`
- 版本说明/补充说明等文档类文件

**不备份：**
- SDK/HAL/库文件（属于工具链安装内容，他人可自行下载）
- 编译产物（`.o` `.hex` `.bin` `.elf` 等）
- IDE 自动生成的无关配置（DebugConfig 等）
- `.git/` 目录

**目录结构保持与原项目一致**，方便别人拿到后直接用对应 IDE 打开。

### 第四步：验证

完成后列一份备份文件夹的完整文件清单，确认无遗漏。
